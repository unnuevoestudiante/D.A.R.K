# M5.1 — Inventario de candidatos y bloqueos de catálogo

**Corte de inspección:** 18 de noviembre de 2026  
**Estado:** CPython Core, Node privado y publicaciones .NET 10.0.15 de prototipo verificados; todavía no existe catálogo publicable de release.
**Alcance:** Windows 11 x64, solo Núcleo v1. El instalador principal no contiene ni descarga modelos.

Este documento registra evidencia para preparar el catálogo firmado. No sustituye el manifiesto ni habilita descargas. Los campos de tamaño, SHA-256, fuente directa versionada y editor deben provenir del archivo concreto de lanzamiento o su procedencia verificable; se dejan pendientes mientras no exista ese artefacto. El source oficial CPython 3.12.16 y sus externals autorizados se descargaron y verificaron; son entradas de compilación, no artefactos de lanzamiento de DARK.

Para respetar Python 3.12 actualizado se eligió source + build oficial `PCbuild`; build y layout embebible están verificados localmente. [Política de soporte .NET](https://dotnet.microsoft.com/en-us/platform/support/policy), [descargas .NET 10](https://dotnet.microsoft.com/en-us/download/dotnet/10.0).

## Bloqueos concretos de M5.1

1. No hay manifiesto de artefactos de release, ni archivos finales desde los que medir bytes y SHA-256.
2. CPython 3.12.16 source + `PCbuild` x64 + runtime privado Core fueron compilados y smoke-tested. Node privado 24.22.3 está medido; Electron 45.3.3 existe localmente y los servicios .NET están autocontenidos sobre 10.0.15. Falta integrar el resto del payload y generar el inventario verificable.
3. Alcance de extras confirmado: Ollama opcional, desmarcado por defecto y descargado solo si se selecciona, sin modificar instancia externa; VLC fuera del paquete base. Ollama v0.40.16 y SHA-256 del asset constan arriba; falta confirmar tamaño exacto y fijar la entrada en el manifiesto firmado.
4. No se ha generado SBOM ni matriz completa de licencias/avisos para dependencias directas y transitivas.
5. La lista de hosts HTTPS de release (`DarkInstaller/release-source-hosts.txt`) no existe. El remoto Git es GitHub, pero eso no equivale a aprobar GitHub Releases como host de descargas ni define una URL estable para el manifiesto vigente. El titular planea compartir builds de prueba de forma directa por Discord/WhatsApp; todavía no se definió el canal para payloads firmados, actualizaciones o reparación. La venta formal queda para una etapa posterior.
6. **Resuelto en código:** `ManifestArtifact` ahora requiere editor, dependencias declaradas y códigos admitidos; valida IDs/referencias/ciclos y exige salida `0` para `runInstaller`. La UI muestra editor, ordena acciones según dependencias y solo acepta los códigos firmados. Falta incorporar estos campos al catálogo real cuando se construya.

No se inventaron versiones, hashes, tamaños ni licencias. Los hashes de entradas y del paquete de prueba están registrados arriba; los hashes finales del release se medirán después de integrar wheels, configuración y runtime al payload completo.
