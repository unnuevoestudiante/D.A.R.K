## Candidato local ensamblado

`tools/installer/assemble_dark_app.py` ensambla el Núcleo sin paquetes Piper/GPL: CPython privado, Wyoming cliente, Node privado, UI Nitro, Electron, DarkSupervisor, ambos Managers y código Python. El candidato actual `.output/release/dark-app-payload-candidate-20261122-compliance-v10/dark-app-payload-candidate.zip` mide 397,792,295 bytes, SHA-256 `c54300d7593c3e7c91d22876d137846dc3d6923f311a538f545b22baaf414f96`; expandido ocupa 914,388,967 bytes en 3,224 archivos. `tools/installer/verify_dark_app_candidate.py` comprobó la igualdad de hashes/tamaños entre ZIP, inventario y layout, además de comparar 2,946 archivos fuente actuales; verificación completada el 22-11-2026. El índice de terceros incluye licencia de runtimes, Python, .NET/NuGet y npm, texto fuente MPL y metadata de licencias de Vite. Este candidato sigue siendo local, unsigned y no publicable.

`tools/installer/assemble_piper_plugin.py` ensambla aparte `.output/release/piper-plugin-candidate-20261121/piper-plugin-win-x64-python312.zip`: 81,528,693 bytes, SHA-256 `105c9f2c9f8dceaf0aebdfe5c91fc65d9d6d0f3ce950d1f00f59906a3b06a1c0`; ocupa 179,629,526 bytes en 2,946 archivos. Incluye CPython propio, ruedas Piper fijadas, worker de proceso independiente y avisos. No contiene voces ni código del Núcleo. Ambos candidatos son unsigned y no publicables.

El inventario base no contiene archivos de memoria, perfiles, tareas, logs, cachés, pruebas, modelos locales ni código/dependencias del motor Piper. El sidecar opcional tampoco contiene voz/modelo. Están rotulados `unsigned-local-candidate-not-for-release` y `unsigned-local-optional-plugin-not-for-release`; no asignan versión/licencia Release ni sustituyen el manifiesto firmado.

El instalador ahora descarga en `%LOCALAPPDATA%\DARK\setup\downloads\<sha256-manifiesto>`, aparte del directorio elegido; extrae cada ZIP en staging temporal, cambia el directorio al completar y conserva una versión previa con sufijo `.previous-*` si actualiza un DARK ya instalado. Al completar el paquete app crea un acceso directo por usuario en el menú Inicio. La validación del destino admite `.` para el paquete base y rutas relativas seguras para extras como `plugins/piper`. El manifiesto Release debe declarar el sidecar como opcional y dependiente del paquete base; si está desmarcado no se descarga.

## Layout instalado elegido

El root de la aplicación contiene `config/runtime.json`, `dark_python/`, `python/` (CPython privado), `node/`, `services/DarkManager/`, `services/DarkTaskManager/`, `DarkSupervisor.exe`, `ui/.output/` y `electron/runtime/` + `electron/app/`. El Supervisor conserva el layout de desarrollo y selecciona el instalado cuando detecta `python/`, `services/` o `ui/`; en instalación exige todas las piezas requeridas. En producción inicia la UI con Node y `.output/server/index.mjs`, no con Vite/NPM.

La ruta predeterminada del instalador es `%LOCALAPPDATA%\Programs\DARK\app`. En el primer arranque instalado, el Supervisor crea la configuración del usuario solo si aún no existe, conserva intacta una configuración previa y crea las carpetas externas de configuración, datos, modelos, logs, temporales y caché. El historial de tareas se escribe en `data`; los logs de ambos managers y las rutas `paths.logs` van a `logs`.

El ZIP embebible CPython 3.12.16 de prueba con las 17 ruedas de `requirements-core.txt` mide 67,715,327 bytes y SHA-256 `2284738264ffe39459d9cdf3e4face94deb3141a20f722b3aba849af6234b366`. El runtime privado importó todas las dependencias directas y ejecutó SQLCipher en memoria. Las ruedas están fijadas en `dark_python/requirements-core-win_amd64.lock.txt`.

El primer prototipo .NET 10.0.9 se reemplazó con .NET 10.0.15. Se descargaron cuatro paquetes NuGet oficiales, limitados por `NuGet.Config`: Microsoft.NETCore.App.Runtime.win-x64 (39,989,758 bytes), Microsoft.AspNetCore.App.Runtime.win-x64 (12,795,364), Microsoft.WindowsDesktop.App.Runtime.win-x64 (39,196,103) y Microsoft.NETCore.App.Host.win-x64 (5,800,874). Sus SHA-256 y los tamaños/hashes de las tres publicaciones se registran en `tools/installer/dotnet-10.0.15-build-inputs.json`. El build usó SDK 10.0.301 y estado de código local; sigue siendo un prototipo, no un release firmado.

## Hallazgos de bloqueo

- El Supervisor ahora resuelve el layout instalado además del de desarrollo. Los tres servicios ya publican autocontenidos con caché local; falta integrar todas las piezas y validar el ciclo desde una instalación limpia.
- El candidato del 22-11-2026 integra las publicaciones actuales de DarkSupervisor, DarkManager y DarkTaskManager. El Supervisor evita conflictos de la UI con puertos configurados u ocupados y persiste en la configuración del usuario la selección automática de un puerto loopback libre. La compilación pasó; la persistencia y el arranque integrado aún deben verificarse en el layout instalado.
- Corregido: `vite.config.ts` fija `node-server` para la distribución local. `npm run build` terminó correctamente y generó `.output/server/index.mjs`, sin `wrangler.json`. Falta probar el arranque de esa salida en el layout final. No se ejecutó instalación npm ni hubo descarga.
- `requirements-core.txt` ya tiene un lock win-x64 CPython 3.12 con hashes. Los perfiles de voz/módulos/web siguen flotantes y fuera del wheelhouse Core.
- M0.1 requiere primera respuesta hablada; se eligió Piper y selección de voz española en primer arranque. Los dos wheels base y las ocho ruedas de dependencia están verificados; la lectura de `METADATA` confirma que la clausura base es completa con `numpy` ya presente en Core, sin activar extras de entrenamiento, web, idiomas u omnivoice. El overlay quedó fijado y validado en una copia aislada del runtime. Aún faltan catálogo/licencias/hashes de voces y la UI de selección. El wheel de Piper contiene dos ONNX internos para procesamiento de idioma; no se descargó ni incorporó la voz española seleccionable. El motor es GPL-3.0-or-later y cada voz tiene licencia propia.
- El lock de Electron es solo una parte del paquete; Electron local 45.3.3 permite armar el layout sin otra descarga, pero falta confirmar ejecución gráfica y preparar avisos completos.
- Node privado 24.22.3 está medido; falta el layout integrado y el aviso de licencia. Node global no se usará en producción.
- Los tres servicios ya publican autocontenidos sobre .NET 10.0.15. La fuente NuGet se restringió a cuatro IDs exactos; los demás paquetes se resolvieron desde caché.
- Una publicación local compilaría código; no probaría la instalación limpia, actualización, reparación, cancelación ni preservación de datos externos.
- Preflight del árbol fuente: `dark_python/gestos.log` mide 59,206,720 bytes. Es un log local excluido del candidato; se conserva intacto en el workspace.
- La selección de modelos/voz en primer arranque y la síntesis con una voz seleccionada siguen pendientes; no se empaqueta una voz ONNX.

En esta continuación: `npm run build`, `npm install --package-lock-only` (484 entradas, sin instalar tarballs), build CPython x64 y wheelhouse Core offline con lock/hash; publicación autocontenida .NET 10.0.15. Se descargaron únicamente los cuatro packs autorizados, desde NuGet.org y con IDs limitados en la configuración de fuentes.
